# Trainer Preparation

## D-7: accounts and access

- [ ] **Claude accounts** for each participant. **No API (Application Programming Interface) key needs to be handed out**:
  everyone signs in with their own account the first time they run `claude`. Options, in order of preference:
  1. **Claude Team / Enterprise seats** of the Keyrus organisation: browser sign-in, usage drawn from the seat's
     quota, spending limits configurable in the admin console;
  2. **members of a Claude Console organisation** (pay-as-you-go billing): browser sign-in
     with the Console account; a "Claude Code" workspace is created automatically, with per-user tracking
     and a spending limit (see "Budget");
  3. **cloud provider** (Amazon Bedrock, Google Cloud, Microsoft Foundry) if traffic must stay inside a cloud account.
  Avoid: a single shared API key distributed via `ANTHROPIC_API_KEY` (no individual tracking, key spread across every machine).
  The only exception: the GitHub Actions demo in half-day 4 uses **one** repository secret (`ANTHROPIC_API_KEY` or
  `CLAUDE_CODE_OAUTH_TOKEN` generated by `claude setup-token`), held by the trainer.
- [ ] **Rate limits**: a training session means everyone working at the same time. The Claude Code documentation
  recommends planning more TPM (tokens per minute) per user when concurrency is high, such as a live training.
  For 12 participants on the Console, aim for at least 100k–150k TPM per user.
- [ ] **Repository**: create the session's GitHub repository from this one (*Use this template* button or fork),
  **without the `solutions/` folder**, and add the participants. Keep `solutions/` on a private `trainer` branch.
- [ ] **Snowflake (optional)**: run [`../snowflake/setup_training_env.sql`](../snowflake/setup_training_env.sql) with an
  `ACCOUNTADMIN` role (or `SYSADMIN` + `SECURITYADMIN`). It creates the `RETAILCO` database, an XS warehouse with 60 s auto-suspend,
  a capped resource monitor, a `TRAINING_ROLE` role and one working schema per participant.
- [ ] Send participants the **prerequisites email** (below) with the repository README.

## Budget and consumption

Official orders of magnitude (Claude Code documentation, *Manage costs* page): in an enterprise, the average cost is
about **$13 per developer per active day**, **$150–250 per month**, and stays under **$30 per active day for 90% of users**.
A training is more intensive than a normal day (everyone explores at the same time, broad prompts):
plan **$15–30 per participant per half-day** on pay-as-you-go billing, i.e. $60–120 per participant
for the 4 sessions, and set the workspace spending limit accordingly.

Levers if consumption runs away: enforce Sonnet as the default model (`/model`), remind people to use `/clear` between exercises,
forbid prompts like "improve the whole repository".
